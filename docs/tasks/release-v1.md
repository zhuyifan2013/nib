# Nib 正式发布路线图

目标：交付可正式发布的完整桌面框架。开发者能在受支持平台安装 Nib，创建应用、开发调试、自动验证、构建安装包、发布和安全更新；agent 可通过稳定的机器接口完成同一闭环。

这是发布目标与待办规划，不代表以下功能已实现或 API 已定稿。基于 2026-10-08 仓库核对；M1 为 macOS 已验证的阶段性交付，原设计的三平台验收仍待补齐。

## 当前基线

2026-10-08：用户授权主 agent 持续统筹路线图，以实现 subagent → 独立 review agent →
修复/复核 → 下一工作包的流程自主推进，无需常规实现确认。当前批次为 M2 增量 2
无头驱动；治理与交接规则见 `autonomous-delivery`。此状态表示整体交付已启动，
不表示全部工作包同时开工或已完成。

- 已交付：macOS 基础窗口与 call 桥、错误信封格式、TS 生成器、开发态后端热替换、事件流与 NDJSON 导出。
- 尚缺：Windows/Linux 运行时及 shell；stream/event 运行时；完整错误因果链；无头驱动、MCP、结构化 CLI；产品级脚手架与构建发行；安全与更新层。
- CLI 当前仅 dev/shell/probe，生成器为独立 nibgen；不能据 README 设计愿景推断 new/build/doctor/ship/audit 已可用。
- 本次规划不重新执行测试；最近复核见 event-stream：2026-10-08 go test ./... 通过，不含新 GUI E2E。

## 发布工作包与验收

### R1：平台与生产运行时

- [ ] 冻结支持矩阵：OS 最低版本、CPU 架构、WebView/工具链要求、Linux 首批发行版；每个组合明确 CI 与实机验证方式。
- [ ] Windows WebView2 / Linux WebKitGTK 实现完整 Window 能力；补齐两平台 dev shell、进程管理与本地传输，验证当前 unix socket 方案的适用性。
- [ ] 本地 Web 资源服务：嵌入资源、自定义 scheme 或等效安全加载方案、MIME、SPA 路由、相对资源、离线启动。
- [ ] 生命周期：退出清理、窗口关闭、重复启动、后台进程与连接回收；确定多窗口与单实例 API。
- [ ] 生产态故障策略：handler panic、后台任务失败、WebView 终止、业务进程退出的观测与恢复边界。开发态两进程不等于生产态故障隔离。
- [ ] 三平台验证输入法、中文路径、高 DPI、窗口缩放和基本可访问性。

验收：同一示范应用在支持矩阵内从安装包离线运行；关闭后无遗留进程；异常均有可解释、可测试的处理结果。

### R2：完整绑定、IPC 与类型契约

- [ ] stream：帧分发、结束/错误、背压、取消、超时、资源回收；明确首版单双向流范围。
- [ ] event：Go → JS 推送、订阅/退订、多订阅者、导航与重连时清理；区分应用事件与诊断事件。
- [ ] call：超时/取消、窗口关闭与断线时终结 pending Promise、并发限制与消息大小限制。
- [ ] 完整 JS → IPC → Go 因果链、调用关联标识、参数脱敏；覆盖本地及 harness 两条路径。
- [ ] Go 服务注册与 TS 生成契约一致，避免当前手写 rt.Bind 与生成签名漂移；补齐真实项目的跨包类型解析与非法签名诊断。
- [ ] 固定公共 API、协议/schema 版本与兼容规则，生成 API manifest / JSON Schema / llms.txt。

验收：call/stream/event 在三平台、直接运行与 dev 模式均通过；取消、断线、慢消费者与异常不会泄漏资源或永久等待。

### R3：M2 诊断与 agent 驱动

- [ ] eval-with-result、截图、DOM 快照、必要的 accessibility tree、navigate/click/fill/调绑定/读事件。
- [ ] 明确隐藏窗口与真正无显示器 CI 的区别，提供各平台可复现的运行环境；不能仅隐藏窗口就宣称无显示器支持。
- [ ] 驱动就绪握手、等待条件、超时、确定性截图与错误输出。
- [ ] 所有公开 CLI 命令支持稳定 --json、错误码、退出码与修复建议，日志与结果分流。
- [ ] MCP 工具覆盖同一驱动 API；内置 inspection 页面用于看事件、调用、错误链与截图。
- [ ] 事件跨进程关联、重放与丢弃语义文档化；诊断端口默认关闭、仅本机绑定并鉴权。

验收：agent 无手动 GUI 交互完成创建应用后的修改、启动、点击/填表、断言、截图与失败定位。

### R4：工具链与开发体验

- [ ] nib new：项目配置/schema、最小 HTML 模板及一个 Vite 模板、后端服务、生成绑定与测试骨架。
- [ ] nib dev：编排前端 dev server/HMR、后端热替换与绑定再生成；处理首次启动、端口冲突、生成失败和退出清理。
- [ ] nib build：前端构建、资源嵌入、Go 构建、版本/图标/平台元数据、可重复执行的产物目录。
- [ ] nib doctor：Go/CGO/编译器、WebView 与系统依赖检测，报告实际支持情况。
- [ ] spec 驱动：先定义可验证的 app.spec 最小 schema 和生成边界，模板生成可重复且不覆盖用户代码。
- [ ] 编译与迭代时间报告，区分首次构建、增量构建与失败；文档写明 CGO 平台构建限制。

验收：干净机器按文档安装后，从 nib new 到 dev/build 无需手改框架源码；修改 Go 方法签名能自动更新绑定并发现前端类型错误。

### R5：M3 安全

- [ ] 权限 manifest 与声明检查、运行时默认拒绝、来源/窗口/绑定权限检查；不能只依赖生成期隐藏客户端方法。
- [ ] 导航、外部链接、iframe 与桥暴露策略；生产包关闭调试/driver/MCP 默认入口。
- [ ] 原生资源路径校验、目录穿越防护、输入与消息大小校验、诊断数据脱敏。
- [ ] nib audit：依赖漏洞扫描、许可证与依赖清单，定义失败阈值与例外记录。
- [ ] 明确 --sandbox 的威胁模型：官方能力 API 的审计无法覆盖任意 Go os/net 调用；若承诺隔离任意后端代码，必须增加 OS 级约束与平台验证。否则准确标注为能力访问报告。

验收：未经授权来源/方法无法越权调用；篡改请求与绕过生成客户端仍被运行时拒绝；审计报告可机器读取且文档准确说明隔离边界。

### R6：M4 系统能力与应用发行

- [ ] 定义并交付首批官方能力：文件/目录选择与读写、应用数据目录、剪贴板、通知、托盘/菜单、外部 URL；各能力接权限、事件、CLI 与驱动接口。
- [ ] 应用包：macOS app/安装分发产物、Windows 安装产物、Linux 首批支持格式；图标、版本、安装/卸载、系统依赖处理。
- [ ] nib ship：可审查的打包/签名/发布配置、渠道与凭据注入；发布前可 dry-run，失败可重试。
- [ ] 签名更新 manifest、完整包与差分包校验、原子替换、断电/下载失败/损坏/启动失败回滚；定义版本与数据迁移策略。
- [ ] UI 动态下发按 frontend-stack 复用 Web 产物，设计签名资源包、缓存、兼容声明与回滚。无需自研 UI DSL。
- [ ] 明确功能模块按需加载形式：首选边界待设计，区分 Web 资源/能力包与原生可执行代码，不能默认用任意远程代码加载。

验收：用户安装后正常启动，从旧版升级到新版，并在损坏包/断网/启动失败场景保留或恢复可用版本；后端与 UI 版本不兼容时拒绝更新。

### R7：验证与真实应用

- [ ] CI：各平台 native 构建与测试、Go 检查、TS 严格类型检查、协议兼容测试、安装包 smoke test。
- [ ] 自动化覆盖：权限拒绝、panic、取消、并发/大消息、流背压、重连、WebView 终止、资源加载与更新回滚。
- [ ] 长时间运行与反复热替换测试：内存、goroutine、句柄和子进程增长有基线与阈值。
- [ ] 两个示范应用：CLI 工具 GUI 壳 + 流/事件实时任务面板；均离线可安装，全程 agent 驱动验证，只有最终视觉确认允许人工。
- [ ] 性能报告：指定硬件/OS/样本应用，测 T_iter <5s、增量编译 <1.5s、热替换 <2s、包体 <10MB、空闲内存 <50MB、冷启动 <1s；明确测量口径与系统 WebView 依赖成本。目标未达时优化或显式重新决策，不能把旧二进制体积当安装包结果。

验收：所有支持组合有可复现测试证据；示范应用能覆盖主能力并公开构建与验证步骤；性能声明均对应可重复基准。

### R8：框架正式发布

- [ ] 框架本身的安装渠道：Go module、CLI 平台二进制；只有提供 npm 包时才发布相应包。核实模块路径、域名控制和包名，验证仓库外 go install / go get。
- [ ] SemVer、稳定 API/schema、兼容政策、迁移指南、CHANGELOG、支持矩阵与已知限制。
- [ ] README/入门/教程/API/错误码/安全模型/发行指南/agent 指南，与实际功能一致。
- [ ] CI 发布流水线：tag、构建、测试、校验和、签名与来源信息、Release notes；密钥通过受控配置提供。
- [ ] 项目维护入口：贡献指南、问题模板、安全漏洞报告渠道、许可证与依赖声明。
- [ ] alpha → beta → RC → stable：每阶段明确退出条件，RC 用外部干净环境完成安装、建应用、发行及升级演练后再正式发布。

验收：新用户仅凭公开文档与公开发布产物即可完成整个闭环；框架发布与框架所构建应用的发行均验证成功。

## 实施顺序

1. 冻结正式版支持矩阵与契约；记录待定产品选择，不提前宣布支持。
2. 完成 M2 无头驱动；补本地资源加载、绑定注册闭环和最小 new/dev/build，使 macOS 端到端可自动验证。
3. 完成 stream/event 与错误链；开发第一个真实应用，建立 CI。
4. Windows/Linux 运行时与 dev harness 对齐，并复用同一协议/E2E 测试。
5. 权限与来源安全、官方能力、doctor/audit/spec/inspection 补齐，完成第二个真实应用。
6. 安装包、签名、更新/回滚、UI 资源更新与模块加载；运行跨平台发行演练。
7. 完成文档、性能与可靠性验证，发 RC，修复发布阻断项后 stable。

平台适配和安全模型设计可在接口稳定后并行推进，但不意味着任务已启动。暂不估日历工期；先按上述验收拆工作包再估算。

## 范围边界与待定项

“完整”以上述发布验收为准；移动端、AI 模型运行时、浏览器内核、自研 UI 框架不在范围。
原设计完整愿景包含 spec、动态 UI、模块加载，均列入本路线图；若希望更早发布，需明确另定义缩减版范围，不能默默删掉并宣称全部完成。

实施前需确定：支持 OS/架构、首批模板与系统能力、生产态多进程策略、stream 双向范围、sandbox 的实际保证、安装包格式、模块加载方式、分发渠道与签名凭据。它们是工作包内的设计/配置项，当前不阻止 M2 驱动继续推进。
