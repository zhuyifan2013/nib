# 生产价值示范性项目

构建若干有生产价值的示范性应用，证明 Nib 的 agent-first 主张：**agent 零手动交互即可交付一个桌面应用**。

## 正式发布的核心验收标准

每个示范应用必须满足：
- 开发与验证全程由 agent 驱动：写代码 → 无头启动（M2）→ 经事件流/桥驱动 UI → 断言状态
- 唯一允许的人工环节是最终的视觉确认（截图）；迭代闭环内不依赖看屏、点鼠标
- UI 回归测试可在无显示器 CI 中运行（依赖 M2 无头驱动 + 事件流）

这条标准是框架级主张的演示：app = API，UI 表面可被机器完整读写——这是相对 Electron/Tauri 的主动差异化，不只是"AI 恰好熟悉 Web 栈"的被动优势。

## macOS 开发者预览里程碑

用 Nib 开发一个类似 macOS Notes 的本地笔记应用。首版建议采用笔记列表和编辑区，支持新建、编辑、自动保存、搜索和删除。富文本、附件、同步与协作留待后续评估。

首个实现批次使用现有的 macOS WebView、Go 后端、`nibgen`、`nib dev` 和本机驱动。用生成的 TypeScript 绑定连接界面与 Go 后端，由 Go 持久化笔记。开发期间遇到的框架缺口记入对应工作包，可离线启动的构建产物作为预览版验收项。

### 预览版验收

- [ ] agent 用本机驱动新建笔记、输入文字、确认自动保存，关闭并重启应用后断言内容一致，再验证搜索和删除。保留截图与结构化事件作为复验依据。
- [ ] 开发者在干净的 macOS 环境按文档完成构建，断网启动构建产物并读写笔记。
- [ ] 在已运行的笔记应用上修改一处 Go 逻辑，经 `nib dev` 热替换后用驱动断言界面结果。记录机器、构建条件及从保存代码到断言通过的耗时，目标 `T_iter < 5s`。

预览使用已验证的 macOS 隐藏窗口模式。无显示器 CI 属于正式发布验收。

## 其他候选方向
- 实时数据/事件面板——会立刻暴露 Go→JS 推送方向（订阅式绑定）的缺口，该方向在桥中尚不存在（当前仅 JS→Go 调用 + 响应）
- CLI 工具的 GUI 壳可用于验证已有命令如何经类型安全绑定接入桌面界面。

## 暴露缺口也是目的
写真实应用才会遇得到的框架空洞（scheme handler、Go→JS 推送、导航策略）应作为发现记录下来，反哺 M2/M3 的 scope。

## 前置依赖
预览原型可使用已验证的 macOS 本机驱动和事件流。正式发布验收依赖 M2 诊断及覆盖支持矩阵的端到端测试。
